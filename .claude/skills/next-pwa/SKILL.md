# @ducanh2912/next-pwa@^10.2.9

Fork/successor of the original `next-pwa` (shadowwalker/next-pwa is unmaintained). Wraps `next.config.ts` to emit a Workbox-generated service worker into `public/sw.js` at build time, plus a Workbox runtime under `public/workbox-*.js`. The README itself nudges new projects toward `@serwist/next` we are intentionally not migrating yet because `@ducanh2912/next-pwa` still ships and our config is small.

## When to use

Reach for this skill when:

- Editing `next.config.ts` and the `withPWA(...)` call.
- Diagnosing "I deployed but users see old chunks" / phantom React errors after a deploy.
- Adding or tuning a `runtimeCaching` rule (e.g. caching Supabase storage images).
- Wiring up an offline fallback page.
- Deciding between `skipWaiting: true` vs. `false`, or between Workbox strategies.

Do NOT use for:

- The PWA manifest. That lives at `src/app/manifest.ts` and is served by Next as `/manifest.webmanifest`.
- The favicon / app icons. Those are referenced from `src/app/layout.tsx` `metadata.icons`.
- Push notifications, background sync, periodic sync not configured in this project.

## Setup in this project

The wrapper is applied in `next.config.ts:14-25`, on top of the next-intl plugin:

```ts
// next.config.ts
import withPWAInit from "@ducanh2912/next-pwa";

const withPWA = withPWAInit({
  dest: "public",
  register: true,
  disable: process.env.NODE_ENV === "development",
  workboxOptions: {
    skipWaiting: false,
    disableDevLogs: true,
  },
});

// Order matters: i18n inner, PWA outer. PWA needs to wrap the final
// resolved config so its webpack plugin sees all transformations.
export default withPWA(withNextIntl(nextConfig));
```

Outputs (production build only):

| File                       | Purpose                                                |
| -------------------------- | ------------------------------------------------------ |
| `public/sw.js`             | Service worker entry, generated by Workbox `GenerateSW`. |
| `public/workbox-<hash>.js` | Workbox runtime modules.                               |
| `public/sw.js.map`         | Source map (excluded from precache by default).        |

Manifest is independent: `src/app/manifest.ts` exports a Next 15+ `MetadataRoute.Manifest` object served at `/manifest.webmanifest`. The PWA plugin does not generate or read it.

`reactStrictMode: true` is set in `next.config.ts:28` relevant because StrictMode double-invokes effects in dev, which can mask service-worker registration timing bugs that only show up in prod.

## API reference

`withPWAInit(options)` returns a function `(nextConfig) => nextConfig`. Key options (full type at `node_modules/@ducanh2912/next-pwa/dist/index.d.ts`):

| Option                          | Default                            | Notes                                                                                              |
| ------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| `dest`                          | `"public"`                         | Where `sw.js` is written. Must be served as a static asset at the site root.                       |
| `disable`                       | `false`                            | We set `process.env.NODE_ENV === "development"` so dev never registers a SW.                       |
| `register`                      | `true`                             | Auto-injects the registration `<script>`. Set to `false` to call `window.workbox.register()` yourself. |
| `sw`                            | `"/sw.js"`                         | URL the registration code points at.                                                               |
| `scope`                         | `nextConfig.basePath` or `"/"`     | URL scope of the SW.                                                                               |
| `cacheStartUrl`                 | `true`                             | Precache the start URL.                                                                            |
| `dynamicStartUrl`               | `true`                             | Use runtime caching for the start URL when its HTML varies (auth state, locale).                   |
| `cacheOnFrontEndNav`            | `false`                            | Extra runtime caching during `next/link` navigation.                                               |
| `aggressiveFrontEndNavCaching`  | `false`                            | Cache every `<link rel=stylesheet>` / `<script>` on FE nav. Requires `cacheOnFrontEndNav`.         |
| `reloadOnOnline`                | `true`                             | Reloads the page when connectivity returns.                                                        |
| `fallbacks`                     | `{}` (auto-detects `app/~offline/page`) | Per-asset-type offline fallback routes. See below.                                            |
| `extendDefaultRuntimeCaching`   | `false`                            | When `true`, your `runtimeCaching` entries merge with the defaults instead of replacing them.      |
| `publicExcludes`                | `["!noprecache/**/*"]`             | Glob negations to skip files in `public/` during precache.                                         |
| `workboxOptions`                | `{}`                               | Forwarded to `workbox-webpack-plugin`. See below.                                                  |
| `customWorkerSrc` / `customWorkerDest` / `customWorkerPrefix` | `"worker"` / `dest` / `"worker"` | For shipping a hand-written worker that gets `importScripts`-ed into the generated SW. |

### `workboxOptions` (most relevant subset of `GenerateSWConfig`)

| Option                      | Default | Notes                                                                                            |
| --------------------------- | ------- | ------------------------------------------------------------------------------------------------ |
| `skipWaiting`               | `true`  | We override to `false` (see Gotchas).                                                            |
| `clientsClaim`              | `true`  | New SW immediately controls existing tabs once activated.                                        |
| `cleanUpOutdatedCaches`     | `true`  | Deletes precaches from older Workbox versions on activate.                                       |
| `runtimeCaching`            | (default array, see `runtimeCaching` export) | An array of `{ urlPattern, handler, options }`. `handler` is one of the strategies below. |
| `disableDevLogs`            | `false` | We set `true` to silence Workbox's chatter when `disable: false` happens to be set.              |
| `ignoreURLParametersMatching` | `[/^utm_/, /^fbclid$/]` | Strip these params before precache lookup.                                              |

Default `runtimeCaching` is also re-exported as `import { runtimeCaching } from "@ducanh2912/next-pwa"` so you can spread + override.

### Workbox strategies (string handlers in `runtimeCaching[].handler`)

These come from `workbox-strategies`. Pick based on freshness vs. resilience tradeoffs:

| Strategy              | Behaviour                                                                                          | Use for                                                |
| --------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `NetworkFirst`        | Try network; on failure or timeout fall back to cache.                                             | HTML pages, JSON API responses you want fresh.         |
| `CacheFirst`          | Serve from cache; only hit network on miss.                                                        | Hashed/immutable assets (fonts, images), audio prompts.|
| `StaleWhileRevalidate`| Return cache instantly, refresh cache from network in background.                                  | Avatars, non-critical CSS, frequently re-fetched data. |
| `NetworkOnly`         | Always network; never cache.                                                                       | POSTs, auth endpoints, anything mutating.              |
| `CacheOnly`           | Always cache; never network. Will fail if not pre-populated.                                       | Precached offline shell content.                       |

Each entry's `options` accepts `cacheName`, `expiration: { maxEntries, maxAgeSeconds }`, `cacheableResponse: { statuses, headers }`, `networkTimeoutSeconds`, and Workbox `plugins` (e.g. `BroadcastUpdatePlugin`).

### `fallbacks`

```ts
fallbacks: {
  document: "/~offline",     // create app/~offline/page.tsx
  image: "/icons/Logo.svg",
  font: "/fonts/fallback.woff2",
  audio: "/audio/silence.mp3",
}
```

For a document fallback the simplest path is to create `app/~offline/page.tsx` and let auto-detection wire it.

## Common patterns

### 1. Production-only registration (current setup)

```ts
const withPWA = withPWAInit({
  dest: "public",
  register: true,
  disable: process.env.NODE_ENV === "development",
  workboxOptions: { skipWaiting: false, disableDevLogs: true },
});
```

This is what `next.config.ts:14-25` does. Dev runs without a SW so HMR / Fast Refresh aren't fighting a cached `_next/static/chunks/*` response.

### 2. Adding a runtimeCaching rule for Supabase Storage images

We allow Supabase Storage hostnames in `next.config.ts:44-48` for `next/image`. To make those images survive offline:

```ts
import { runtimeCaching as defaultRuntimeCaching } from "@ducanh2912/next-pwa";

const withPWA = withPWAInit({
  dest: "public",
  register: true,
  disable: process.env.NODE_ENV === "development",
  workboxOptions: {
    skipWaiting: false,
    disableDevLogs: true,
    runtimeCaching: [
      {
        urlPattern: ({ url }) => url.hostname.endsWith(".supabase.co"),
        handler: "StaleWhileRevalidate",
        options: {
          cacheName: "supabase-storage",
          expiration: { maxEntries: 200, maxAgeSeconds: 60 * 60 * 24 * 30 },
          cacheableResponse: { statuses: [0, 200] },
        },
      },
      ...defaultRuntimeCaching,
    ],
  },
});
```

Note: `cacheableResponse.statuses` includes `0` so opaque cross-origin responses are cacheable.

### 3. Manual registration (when `register: false`)

The README ships a copy-pasteable `RegisterPWA` client component. Drop it into `src/app/layout.tsx` next to `<AppHydration />`:

```tsx
"use client";
import { useEffect } from "react";
import type { Workbox } from "workbox-window";

declare global {
  interface Window { workbox: Workbox }
}

export default function RegisterPWA() {
  useEffect(() => {
    if ("serviceWorker" in navigator && window.workbox) {
      window.workbox.register();
    }
  }, []);
  return null;
}
```

### 4. Update flow with `skipWaiting: false`

When the user opens the app and a new SW is found, it stays in `waiting`. To prompt the user to reload:

```tsx
"use client";
import { useEffect, useState } from "react";

export function UpdatePrompt() {
  const [waiting, setWaiting] = useState<ServiceWorker | null>(null);

  useEffect(() => {
    if (!("serviceWorker" in navigator) || !window.workbox) return;
    const wb = window.workbox;
    const onWaiting = () => setWaiting(wb.waiting ?? null);
    wb.addEventListener("waiting", onWaiting);
    return () => wb.removeEventListener("waiting", onWaiting);
  }, []);

  if (!waiting) return null;
  return (
    <button
      onClick={() => {
        waiting.postMessage({ type: "SKIP_WAITING" });
        waiting.addEventListener("statechange", (e) => {
          if ((e.target as ServiceWorker).state === "activated") {
            window.location.reload();
          }
        });
      }}
    >
      Reload to update
    </button>
  );
}
```

## Gotchas

### Stale service workers serving cached chunks → phantom React errors (this project hit this)

Symptom: in production, after a deploy, users saw React errors like `Minified React error #418` / `Hydration failed because the initial UI does not match` / mysterious `undefined is not a function` from chunks that no longer exist in the new build. The errors went away after a hard refresh.

Root cause: an old `sw.js` still controlled the tab, served a precached `_next/static/chunks/<oldhash>.js` whose imports referenced symbols that the new HTML's hashed chunks don't expose. React was effectively running mismatched bundles.

Mitigations we apply:

1. `skipWaiting: false` new SW waits until all tabs reload, so a session never mid-mixes old + new chunks.
2. Default `cleanUpOutdatedCaches: true` old precache buckets are deleted on activate.
3. The default Next/Workbox precache excludes are `[/\/_next\/static\/.*(?<!\.p)\.woff2/, /\.map$/, /^manifest.*\.js$/]` do not over-broaden these without thinking, but be aware that runtime caches you add can themselves go stale.
4. When debugging in prod, the only reliable client-side reset is DevTools → Application → Service Workers → "Unregister", then hard reload. Tell users to close all tabs of the app.

If you ever toggle `skipWaiting: true`, ship an `UpdatePrompt`-style UX too, otherwise users hit this again.

### App Router quirks

- `register: true` injects a `<script>` tag fine with App Router. If you wrote your own root `<Document>` (Pages Router idiom), that path doesn't apply here.
- Auto-detected document fallback expects `app/~offline/page.tsx` (note the tilde). With Pages Router it was `pages/_offline.tsx`.
- `dest: "public"` is non-negotiable on App Router Next's static asset pipeline is what serves `sw.js` at the origin.

### Next 16 specifics

- `next.config.ts` works (TypeScript config files are first-class). Ensure `withPWA` wraps the OUTERMOST config so its webpack plugin observes the final compiled options. We have:
  ```ts
  export default withPWA(withNextIntl(nextConfig));
  ```
  `next.config.ts:51-53` documents the order. Reversing it has historically broken next-intl's plugin detection.
- `allowedDevOrigins` (`next.config.ts:41`) is unrelated to PWA but lives in the same file; do not collapse the PWA wrapper around a stray `module.exports = {}` that historic mistake clobbered exports before plugins could attach (see comment in `next.config.ts:35-40`).
- Turbopack: as of 10.2.9 the plugin is webpack-only. `next dev --turbo` runs without the SW (and we already disable in dev). Production builds use webpack regardless, so this is fine for now.

### Other footguns

- The package has not had a release since Sep 2024 (10.2.9). For new projects the README itself recommends migrating to `@serwist/next`.
- `disable: true` does NOT remove an already-installed SW from a returning user's browser. Ship a one-shot unregister script if you ever need to fully back the PWA out.
- `runtimeCaching` entries are evaluated in order and the FIRST match wins. Put narrow `urlPattern`s before broad ones and if you spread `defaultRuntimeCaching`, decide whether your overrides go before or after.
- `urlPattern` can be a `RegExp` or a function `({ url, request, sameOrigin }) => boolean`. Functions are easier to reason about than complex regexes.
- `workboxOptions.exclude` defaults exclude `.map$` if you ship a custom worker make sure you don't accidentally re-include source maps in the precache manifest.
